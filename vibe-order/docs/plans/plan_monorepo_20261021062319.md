# vibe-order モノレポ雛形 構築計画

## Context

Day3 ハンズオンでは、Day2 の Vibe Coding で起きた問題（品質のばらつき、秘密情報の混入、テストなし）を「仕組みで防ぐ」ための開発基盤を作る。
`vibe-order/` はまだ存在しない。npm workspaces のモノレポ雛形（shared / backend / frontend）を作り、
Format / Lint / Test / Build が CI とコミット前フックで自動的に通ることを確認できる状態にする。
今回は雛形だけを作る。注文機能などのアプリ実装は範囲外とする。

## 前提・確認済みの事実

- 実行環境: Node.js v24.21.0 / npm 11.19.0（devcontainer: `typescript-node:24-bookworm`）
- git のルートはリポジトリルート。`vibe-order/` はサブディレクトリなので、Husky と CI はサブディレクトリ構成に合わせる
- gitleaks は未インストール（npm パッケージではなく Go 製の単体バイナリ）
- `vibe-order/docs/ref/`（llms.txt 置き場）はまだ存在しない
- `.github/` もまだ存在しない

## 方針（KISS / 依存最小化）

| 項目 | 方針 | 理由 |
|---|---|---|
| Biome | ルートに `biome.json` を1つだけ置き、`biome check .` で全パッケージを対象にする | 設定の重複を避ける |
| Vitest | ルートの `vitest.config.ts` で `test.projects: ['packages/*']` を使う | ルートで `npx vitest --run --coverage` を実行すれば全パッケージのカバレッジが1つのレポートにまとまる（CLAUDE.md のコマンドと一致） |
| TypeScript | `tsconfig.base.json` を各パッケージの tsconfig が extends する | 共通設定を1か所にまとめる |
| shared | `tsc` で `dist/` にビルドし、`exports` で `dist` の js と d.ts を公開する | backend の tsc と frontend の Vite がどちらも同じ方法で解決できる。そのためテストの前に shared をビルドする |
| backend の開発実行 | `tsx` は入れず、Node 24 の型除去機能を使う（`node --watch src/index.ts`） | 標準機能で代替できる。tsconfig に `erasableSyntaxOnly` と `rewriteRelativeImportExtensions` を設定する |
| frontend のユニットテスト | Testing Library と jsdom は入れず、`react-dom/server` の `renderToString` で検証する | 追加の依存なしでコンポーネントの出力を確かめられる |
| E2E | Playwright は `npm run test:e2e` に分け、`npm run test` には含めない | CLAUDE.md の「E2E はユニットテスト成功後の最終チェック」に従う |
| gitleaks | pre-commit で `gitleaks git --pre-commit --staged` を実行し、**未インストールならコミットを失敗させる** | 黙ってスキップすると安全性が下がるため |
| gitleaks の導入 | インストール用のスクリプト `.devcontainer/install-gitleaks.sh` を1つ作り、devcontainer と CI の両方で使う。版を固定し、チェックサムで検証する | 版の指定を1か所にまとめる。改ざんされたバイナリを防ぐ |
| CI の gitleaks | `gitleaks-action` は使わず、バイナリを直接実行してリポジトリの履歴全体（`fetch-depth: 0`）をスキャンする | `--no-verify` でフックを回避されても、マージ前に検出できる。履歴は 33 コミットと小さく、追跡されている `.env` や鍵ファイルも無いことを確認済み |

## イテレーション（それぞれ 30 分以内）

各イテレーションは TDD（Red → Green → Refactor）で進め、最後に `npm run check` と `npm run test` を通す。
コマンドは特に断りがなければ `vibe-order/` で実行する。

### Iteration 0: 事前確認と記録の準備

- `npm view <pkg> version license` で、上の表のパッケージの最新版とライセンスを確認する。MIT / Apache-2.0 / BSD 以外があれば作業を止めて相談する
- `vibe-order/docs/memo.md` を作り、追加するライブラリ・版・理由を記録する
- 使い方に自信がないライブラリ（Hono、Vitest projects、Tailwind v4、Husky のサブディレクトリ構成など）の llms.txt を `vibe-order/docs/ref/` に保存する
- **完了条件**: `npm view` の結果が memo.md に記録されている。`ls vibe-order/docs/ref` で llms.txt が確認できる

### Iteration 1: ルートの雛形（workspaces / Biome / TypeScript / Vitest）

- ルートの `package.json`（`private: true`、`workspaces`）、`biome.json`、`tsconfig.base.json`、`vitest.config.ts`、`.gitignore` を作る
- 3つのパッケージの `package.json` だけを作る（名前は `@vibe-order/shared` などにする）
- **完了条件**:
  - `npm install` が成功する
  - `npm run check` が成功する
  - `npm audit` で脆弱性が 0 件

### Iteration 2: shared（Zod スキーマ）

- Red: `HealthResponseSchema`（例: `{ status: 'ok' }`）を検証するテストを書く
- Green: Zod でスキーマと `z.infer` の型を実装し、`src/index.ts` から export する
- `tsc` で `dist/` に出力し、`exports` で公開する
- **完了条件**: `npm run test`、`npm run build -w @vibe-order/shared`、`npm run check` が成功する

### Iteration 3: backend（Hono）

- Red: `app.request('/health')` が 200 を返し、本文が `HealthResponseSchema` に合うことを確認するテストを書く
- Green: `src/app.ts` に Hono アプリを書き、`src/index.ts` で `@hono/node-server` の `serve()` を使ってポート 3000 で起動する
- scripts: `dev`（`node --watch src/index.ts`）、`build`（`tsc`）、`start`（`node dist/index.js`）
- **完了条件**:
  - `npm run test`、`npm run build`、`npm run check` が成功する
  - `npm run start -w @vibe-order/backend` で起動し、`curl -s localhost:3000/health` が `{"status":"ok"}` を返す

### Iteration 4: frontend（React / Vite / Tailwind）

- Red: `renderToString(<App />)` の出力に見出しのテキストが含まれることを確認するテストを書く
- Green: Tailwind のクラスを使った `App.tsx`、`main.tsx`、`index.css`（`@import "tailwindcss";`）を作る。`vite.config.ts` に React と Tailwind のプラグインを設定する
- scripts: `dev`（`vite`）、`build`（`tsc --noEmit && vite build`）
- **完了条件**: `npm run test`、`npm run build`、`npm run check` が成功する。`npm run dev -w @vibe-order/frontend` で 5173 番ポートの画面が表示される

### Iteration 5: Playwright（E2E）

- `playwright.config.ts`（`webServer` で `vite preview` を起動、Chromium のみ）と `e2e/app.spec.ts`（見出しが表示されること）を作る
- Vitest が `e2e/` を拾わないように `exclude` を設定する
- **完了条件**:
  - `npx playwright install --with-deps chromium` のあとに `npm run test:e2e` が成功する
  - `npm run test` に E2E が含まれていない

### Iteration 6: カバレッジ

- ルートの `vitest.config.ts` に `coverage`（provider: v8、`thresholds` は lines / functions / branches / statements すべて 80）を設定する
- 起動処理だけのファイル（`backend/src/index.ts`、`frontend/src/main.tsx`）は対象から外す。外したファイルは memo.md に記録する
- **完了条件**: `npx vitest --run --coverage`（または `npm run coverage`）が成功し、全パッケージが 80% 以上

### Iteration 7: Husky + lint-staged + gitleaks

- Husky v9 をサブディレクトリ構成で設定する（`prepare: "cd .. && husky vibe-order/.husky"`）
- `.husky/pre-commit` の処理:
  1. `cd vibe-order`
  2. `gitleaks` が無ければメッセージを出して `exit 1`
  3. `gitleaks git --pre-commit --staged --redact`
  4. `npx lint-staged`（`biome check --write --no-errors-on-unmatched`）
  5. `npm run test`
- gitleaks の導入（合意済み）:
  - `.devcontainer/install-gitleaks.sh` を作る。処理は次のとおり
    1. `GITLEAKS_VERSION` を固定する（Iteration 0 で最新版を確認する）
    2. `uname -m` で x64 か arm64 かを判定する
    3. 公式リリースから tar.gz と `gitleaks_<版>_checksums.txt` を取得する
    4. `sha256sum -c` で検証し、失敗したら `exit 1`
    5. `sudo install` で `/usr/local/bin` に配置する
  - `.devcontainer/devcontainer.json` の `postCreateCommand` をオブジェクト形式に変える。既存の Claude 設定の処理はそのまま残し、`"gitleaks": "bash .devcontainer/install-gitleaks.sh"` を追加する
  - 今の Codespace では、このスクリプトを手動で実行する（Rebuild はしない）
- **完了条件**（コミットはしない）:
  - `bash .devcontainer/install-gitleaks.sh` が成功し、`gitleaks version` で固定した版が表示される
  - `gitleaks git --redact` をリポジトリ全体に実行して、検出が 0 件（検出があれば作業を止めて相談する）
  - `git config core.hooksPath` が `vibe-order/.husky/_` を指している
  - ダミーの秘密情報を含むファイルを stage して `sh vibe-order/.husky/pre-commit` を実行すると失敗する（確認後に unstage して削除する）
  - Lint エラーを含むファイルを stage すると失敗する（確認後に元に戻す）
  - 正常な状態では `sh vibe-order/.husky/pre-commit` が成功する

### Iteration 8: GitHub Actions CI

- `.github/workflows/vibe-order-ci.yml`（リポジトリルートに置く）:
  - `on: [push, pull_request]`、`permissions: contents: read`
  - `defaults.run.working-directory: vibe-order`、`env: HUSKY: 0`
  - `actions/checkout`、`actions/setup-node`（`node-version: 24`、`cache: npm`、`cache-dependency-path: vibe-order/package-lock.json`）は、実装時点の最新メジャー版を使う
  - job `check-test-build`: `npm ci` → `npm run check` → `npm run test` → `npm run build`
  - job `gitleaks`（合意済み）:
    - `gitleaks-action` は使わない
    - `actions/checkout` は `fetch-depth: 0` で履歴全体を取得する
    - `bash .devcontainer/install-gitleaks.sh` でインストールし、`gitleaks git --redact --verbose` を実行する
    - スキャン対象はリポジトリ全体なので、この job だけは `working-directory` をリポジトリルートにする
- **完了条件**:
  - `gitleaks git --redact` をローカルで実行して、検出が 0 件
  - CI と同じコマンドをローカルで実行して成功する: `npm ci && npm run check && npm run test && npm run build`
  - push 後に Actions が成功する（push はユーザーが Day3 手順 4 で行う。こちらでは commit / push しない）

## 全体の検証（タスクの完了条件）

```bash
cd vibe-order
npm ci

```
