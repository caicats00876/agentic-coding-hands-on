# Day4 チューター用ガイド

手順書：`../docs/Day4_AgenticCodingで実装.md`

## この日のねらい

「計画 → レビュー → TDD → セルフチェック → Pull Request → CI」のサイクルを、パッケージごとに回させます。最も遅れが出やすい日です。frontend は Day5 の前半まで延長してよいことを、最初に伝えます。

## ステップごとの確認点

### ハンズオン 0：llms.txt の取得

*   `curl` は権限設定で禁止されているため、受講者が自分のターミナルで実行します。

### 開発サイクル（shared → backend → frontend）

*   パッケージごとに**新しい会話**を始めているかを確認します。会話が長くなると AI の品質が落ちます。
*   計画のレビュー観点（先に書くテスト、shared の再利用、受け入れ条件とテストの対応）を確認させます。
*   AI がテストを書かずに実装を進めていたら、受講者から AI に「テストはどこ？」と聞かせます。あなたが代わりに指摘するのではなく、受講者に気づかせます。
*   `/selfcheck` の報告と、受講者自身が実行した `npm run check`、カバレッジの結果を突き合わせます。
*   Pull Request の CI が成功しているかを、GitHub の画面で確認します。

### frontend

*   Codespaces の **PORTS** タブから画面を開き、席の画面とキッチン画面を別タブで並べて確認させます。

## 遅れたときの調整

| 状況 | 調整 |
| :--- | :--- |
| backend が終わらない | frontend をキッチン画面だけに絞る |
| frontend が終わらない | Day5 の前半まで延長する（予定どおり） |
| 会話が長くなり AI の動きが怪しい | `resume.template.prompt.txt` で新しい会話から再開させる |
