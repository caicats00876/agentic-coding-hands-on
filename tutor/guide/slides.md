# スライド（研修の概要説明用）

研修の概要を説明するスライドです。受講者に Chrome で開いてもらい、ページを見ながら説明します。

*   URL：https://caicats00876.github.io/agentic-coding-hands-on/docs/slides/agentic-coding-training.html
*   そのまま開くと1枚目（表紙）から始まります。途中のページへすぐ移りたいときだけ、URL の末尾に `#番号` を付けます（例：4つの作法の8枚目は `…/agentic-coding-training.html#8`）
*   ページ送りは受講者が行います：`→` キーか `Space` で次へ、`←` キーで前へ

オリエンテーションの時点では、あなたは Chrome の画面を見られません（Claude in Chrome は Day1 ハンズオン 1-3 でつなぎます）。受講者に URL を開いてもらい、「いま何枚目を見ていますか」と確かめながら進めます。下の「話すこと」は、スライドの発表者ノートをもとにしています。言い回しは受講者に合わせてかまいません。

## オリエンテーションで使うページと順番

## ページごとの内容

### 1. 表紙（`#1`）

*   書いてあること：Agentic Coding 体験研修。Vibe Coding の手軽さから、AI と品質を両立する開発へ。5日間、新入社員・AI 駆動開発入門者向け。ベース教材は書籍『Agentic Coding　生成AI時代のシステム開発入門』
*   話すこと：座学ではなく、手を動かして Agentic Coding を体験する研修です。Vibe Coding の手軽さを体験し、その問題点に直面し、Agentic Coding で解決する流れで進みます。

### 2. 研修のねらい（`#2`）

*   書いてあること：体験が主役（座学は各日30分程度、8割以上は手を動かす）、対象者、ゴール（「AI にどう委ねればよいか」を自分の体験と数字で説明できる）
*   話すこと：書籍の内容を網羅するのではなく、体験を通じて AI への委ね方を身につけます。AI チューターと一緒に一人で進め、最終日に振り返り発表をします。

### 3. 便利さ → 失敗 → 解決 → 実感（`#3`）

*   書いてあること：Day1 手軽さを体験、Day2 問題点に直面、Day3-4 解決する、Day5 効果を実感
*   話すこと：Day1〜2 はあえて Vibe Coding のまま進めます。問題に自分で気づくことが、Day3 以降の学びの動機になります。ここが研修でいちばん大事な流れです。

### 4. 5日間の時間割（`#4`）

*   書いてあること：各日のテーマ、主な体験、書籍の該当 PART。1日分はおよそ7〜8時間、自分のペースで進める
*   話すこと：時間割は目安です。区切りのよいところで中断でき、再開メモで続きから始められます。

### 5. 研修環境（`#5`）

*   書いてあること：GitHub Codespaces（クラウドの隔離環境なので、AI が失敗しても PC は無傷）、Claude Code（VS Code のチャットパネルから指示）、GitHub Actions（CI）。書籍の Cline・Amazon Bedrock・AWS は、この環境に読み替える
*   話すこと：ブラウザは Chrome を使います。細かい操作は、このあとのハンズオンで1ステップずつ案内します。

### 6. Day1 環境構築と Vibe Coding 体験（`#6`）

*   書いてあること：今日の流れ、Vibe Coding のルール（自然言語だけで指示、提案はそのまま承認、コードは読まない）
*   話すこと：今日はコードを読みません。完成度に差が出ても問題ありません。動かない部分があること自体が Day2 の材料になります。「読まなかったこと」の代償は、翌日体験します。

### 7. Day2 Vibe Coding の限界に直面する（`#7`）

*   書いてあること：機能追加（60分で打ち切り）、品質を自分で調べる、問題を4つに分類する（曖昧な要件、検証条件がない、スタイル不統一、致命的なミス）。午後はガードレールと Plan モード
*   話すこと：品質検証は AI に頼らず、自分でコマンドを実行します。

### 8. お願いではなく、仕組みで強制する（`#8`）

*   書いてあること：4つの問題と、4つの作法（要件定義の具体化、自動テスト、規約の維持、ガードレール）、研修で使う仕組みの対応表
*   話すこと：Day2 午後のミニ講義の中心の表です。午前に見つけた問題と対応づけて説明します。AI に「気をつけて」とお願いするのではなく、テストや CI や権限設定で強制します。

### 9. Day3 開発基盤構築と要件の具体化（`#9`）

*   書いてあること：CLAUDE.md とカスタムコマンド、Plan モードでモノレポを計画・レビュー・構築、Pull Request と CI、要件から設計書。書籍（Cline）の用語との対応
*   話すこと：計画は読んでから承認し、1つ以上の修正依頼を出します。

### 10. Day4 開発サイクルを3回まわす（`#10`）

*   書いてあること：計画 → レビュー → TDD → /selfcheck → PR と CI。shared → backend → frontend。カバレッジ80%以上
*   話すこと：最も遅れが出やすい日です。frontend は Day5 の前半まで延長してかまいません。パッケージが変わるたびに新しい会話を始めます。

### 11. Vibe Order（`#11`）

*   書いてあること：MVP の機能（席から注文、キッチン画面に即時表示、受付 → 調理中 → 提供済、キャンセルは受付のときのみ、WebSocket の自動再接続）、AWS 構成からの置き換え
*   話すこと：書籍の要求仕様を研修用に絞っています。拡張課題は時間が余ったときに取り組みます。

### 12. Day5 同じ変更依頼で Before/After を比較する（`#12`）

*   書いてあること：比較の観点（手戻り、デグレ、気づいたきっかけ、テスト数・カバレッジ、安心感）
*   話すこと：比べるのは速さだけではありません。壊れたことにすぐ気づけるか、安心して変更できるかを比べます。

### 13. 評価の観点（`#13`）

*   書いてあること：5つの観点（問題の言語化、計画のレビュー、品質のゲート、ガードレール、振り返り）と提出物
*   話すこと：最終日に AI チューターと一緒に自己評価します。

### 14. AI チューターと一緒に進める（`#14`）

*   書いてあること：案内と講義、画面で確認、対話の相手。操作するのは自分で、AI チューターは代わりに作業しない
*   話すこと：アカウントの登録、Codespace の操作、プロンプトの送信は、すべて自分で行います。AI チューターは案内と確認だけを行います。

### 15. 2つの Claude（`#15`）

*   書いてあること：① AI チューター（Claude デスクトップアプリのチャット）と ② Claude Code（VS Code の ✳ パネル）の図
*   話すこと：5日間でいちばん大事な図です。研修の進め方は ① に、アプリを作る作業は ② に話しかけます。会話も別々です。

### 16. まとめ（`#16`）

*   書いてあること：人が意図を示し、AI が作り、人が責任をもって仕上げる
*   話すこと：Day5 の締めくくりに使います。明日から自分の業務で、まず何を整えるか（CLAUDE.md、テスト、CI、権限設定）を考えてもらいます。
