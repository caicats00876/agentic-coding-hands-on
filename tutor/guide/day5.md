# Day5 チューター用ガイド

手順書：`../docs/Day5_仕上げ・BeforeAfter比較・発表.md`

## この日のねらい

Vibe Order を E2E テストと CI で守られた状態にし、Day2 と同じ種類の変更依頼で Before/After を比べます。最後に、受講者が5日間を振り返って発表し、自己評価をします。

## ステップごとの確認点

### ハンズオン 1：起動と公開

*   ポートの公開範囲が **Private** のままか確認します。**Public にはさせません。**

### ハンズオン 2：E2E テストと CI

*   時間が足りなくなりそうなら、E2E を簡略化して、変更依頼による比較の時間を確保します。

### ハンズオン 3：Before/After の比較（研修の山場）

*   計画のレビューで、**期待値が変わる既存テスト**が挙げられているかを確認させます。
*   比較シートの「Vibe Order（Day5 変更）」列を、Day2 と同じ観点で埋めさせます。
*   「速さ」だけでなく、「壊れたことにすぐ気づけるか」「安心して変更できるか」に注目させます。

### ハンズオン 4：振り返り発表（チーム発表の代わり、目安 準備 30分＋発表 10分＋質疑 5分）

1.  受講者が `../docs/worksheets/発表テンプレート.md` に沿って準備します。
2.  あなたが聞き手になります。受講者は、発表の内容をチャットに書くか、画面に映して説明します。
3.  質疑では、数字の比較だけでなく「**自分の役割がどう変わったか**」を語ってもらいます。
    *   「Day1 と Day5 で、あなたが時間を使ったところはどう変わりましたか」
    *   「明日の業務で、まず何を整えますか」

### ミニ講義：本番リリースに向けて（目安 30分）

*   手順書の要点を説明し、実務で最初に整える仕組みを受講者に決めてもらいます。

### 自己評価（目安 30分）

*   `evaluation.md` に沿って、受講者と一緒に自己評価をします。

## 遅れたときの調整

| 状況 | 調整 |
| :--- | :--- |
| E2E が終わらない | E2E は1フロー（注文 → キッチン表示）だけにする |
| 比較の時間が取れない | E2E を簡略化し、変更依頼を優先する |
