# Day1 チューター用ガイド

手順書：`docs/Day1_環境構築とVibeCoding体験.md`

## この日のねらい

AI エージェントの速さと手軽さを体験させます。完成度に差が出ても問題ありません。動かない部分があること自体が、Day2 の材料になります。

## ステップごとの確認点

### オリエンテーション（目安 30分）

*   **スライドを使って説明します。**受講者に、Chrome で次の URL を開いてもらいます。
    *   https://caicats00876.github.io/agentic-coding-hands-on/docs/slides/agentic-coding-training.html
*   使うページは 1〜4 → 14〜15 → 5〜6 の順です。ページごとに話すことは `tutor__guide__slides.md` にあります。4 枚目のあと 14 枚目に移るときは、`→` キーで進めても、URL の末尾に `#14` を付けて開き直してもかまいません。
*   この時点では、あなたはまだ Chrome の画面を見られません（Claude in Chrome はハンズオン 1-3 でつなぎます）。「いま何枚目を見ていますか」と確かめながら、受講者にページを進めてもらいます。
*   スライドが開けない場合は、README の「研修のストーリー」と「5日間の内容」をもとに文章で説明します。
*   研修のルール（Vibe Coding のルール）と、毎日の記録（比較シート、日報）を伝えます。
*   この研修は一人で進めること、あなたが講師役であること、作業はすべて受講者が行うことを伝えます。

### 道具の使い方（目安 20分）

*   受講者に Chrome で `docs/道具の使い方.md` を開いてもらい（GitHub 上の URL は指示文の「受講者に図やページを見せるとき」）、2つの Claude の図を見ながら違いを説明します。ここが5日間でいちばん大事な図です。この時点ではあなたは Chrome を使えないので、受講者に開いてもらいます。
*   あなたの指示には【Claude Code に送る】【ターミナルで実行】【ブラウザで操作】【チューターへ】の表記が付くことを伝えます。
*   受講者に、自分の言葉で「① と ② の違い」を説明してもらいます。言えなければ、もう一度図で説明します。
*   `docs/道具の使い方.md` の残り（VS Code の画面、ターミナル、Git の言葉）は、ざっと紹介するだけにします。使う場面で、もう一度説明します。

### ミニ講義：LLM と Coding Agent（目安 15分）

*   手順書の「ミニ講義のポイント」を、身近な例を交えて要約します。

### ハンズオン 1：アカウントと環境の準備

受講者が自分で登録します。あなたは手順を案内し、画面を確認するだけです。

| 手順 | 確認すること |
| :--- | :--- |
| 1. 作業用の Google アカウント | 自社のメールアドレスで作ったか。すでに作業用のアカウントがある人は、それを使ってよい |
| 2. Chrome の作業用プロファイル | プロファイルにそのアカウントでログインしたか。以降の作業は、すべてこのプロファイルで行う |
| 3. Claude in Chrome | 作業用プロファイルに追加し、社内契約の Claude アカウントでサインインしたか。ここで接続を確認する。以降は画面を直接見られる |
| 4. GitHub アカウント | 自社のメールアドレスで登録し、メール認証まで済んだか |
| 5. fork | 自分のアカウントに fork したか（fork の URL を再開メモに書く） |
| 6. 待ち時間（idle timeout） | https://github.com/settings/codespaces の Default idle timeout を 120 分にしたか。作業中に止まると、Vibe Chat の作成中に中断する |
| 7. Codespace | recovery mode になっていないか。✳ が出ないときは、拡張機能の画面で「Claude Code for VS Code」（提供元 Anthropic）を受講者にインストールしてもらう。左下のブランチ、Claude のアイコン（✳）、`node -v` が v24 系か。手順書の VS Code の画面の図で、5つの場所を確認させる |
| 8. 信頼ダイアログとクリップボード | 「フォルダーを信頼して続行」を選んだか。クリップボードを許可し、貼り付けができるか |

*   Claude in Chrome がつながるまでは、受講者の報告やスクリーンショットで確認します。
*   Codespace は、自分のタブグループに開いて確認します（受講者が開いたタブは見えません）。

### ハンズオン 2：Claude Code へのサインイン

*   ここで初めて ② Claude Code を使います。「今から話しかける相手は、私（AI チューター）ではなく Codespace の中の Claude です」と、図を使ってもう一度伝えます。
*   右側に最初から出ている「チャット」は Copilot です。Claude のアイコン（✳）から開いたパネルを使っているかを確認します。
*   認証コードは受講者が自分で貼り戻します。コードを共有しないよう、ここで一度注意します。
*   応答が英語なら、`/config` で language を `japanese` にするよう案内します。

### ハンズオン 3：ウォーミングアップ

*   モードを **Manual** にしてから始めさせます（最初は Auto になっていることがあります）。
*   話題ごとに新しい会話（＋）を始めさせます。
*   観察ポイントの答えを、受講者に言葉で説明してもらいます。失敗が起きなければ「失敗したとき」の観察は Vibe Chat に回します。
*   確認ダイアログで「常に許可」を押すと、設定ファイルに書き込まれます。試走では、個人用の `.claude/settings.local.json` ではなく、**共有用の `.claude/settings.json`** に書き込まれ、`rm -rf`、`curl`、`npm i *` まで含まれていました。今日は触らず、コミットもさせません。Day2 の権限設定の教材にします。

### ミニ講義：Vibe Coding とは（目安 15分）

*   ルール3つを確認し、「ここからは確認ダイアログの中身を考えずに承認する」と伝えます。

### ハンズオン 4：Vibe Chat を作る（目安 3時間）

*   開始時刻を記録します。指示の回数と、エラーを貼って直させた回数を、受講者に数えてもらいます。
*   モードは **Edit automatically** です。エディタで開いているファイルが会話に自動で添付されるので、外してから送るよう伝えます。
*   受講者が「コードを読んでもいいですか」と聞いたら、「今日は読まないでください」と答えます。
*   正しいやり方（テストを書かせる、計画をレビューする など）は、先に教えません。
*   起動したら、ポート転送の URL を受講者に開いてもらい、画面を一緒に確認します。URL が分からないときは、ポートタブの地球儀アイコンか、Claude Code に「アクセスする URL を教えて」と聞くよう案内します。
*   2人のユーザーで試すときは、2人目をシークレットウィンドウで開かせます。

### チーム内の見せ合いの代わり（目安 20分）

完成した Vibe Chat を画面で見せてもらい、次の問いに答えてもらいます。答えは日報の材料になります。

*   何ができて、何ができなかったか
*   一番驚いたことは何か
*   このアプリを、そのままお客様に納品できると思うか

### 記録（目安 30分）

*   `git add vibe-chat && git commit` まで受講者が行ったことを確認します。
*   比較シートと日報は、手順書の「6. 記録する」のコマンドで、自分用のファイルを作って開きます。受講者は Markdown を書いたことがないので、あなたが**項目だけのひな形**をコードブロックで示し、受講者はそれを `Ctrl+V` で貼って数字や言葉を書き込むだけにします。
*   問いの答えは、受講者自身の言葉で書いてもらいます。あなたが下書きしません。
