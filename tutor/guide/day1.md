# Day1 チューター用ガイド

手順書：`../docs/Day1_環境構築とVibeCoding体験.md`

## この日のねらい

AI エージェントの速さと手軽さを体験させます。完成度に差が出ても問題ありません。動かない部分があること自体が、Day2 の材料になります。

## ステップごとの確認点

### オリエンテーション（目安 30分）

*   内蔵ブラウザでスライドの 1〜6 枚目を開き、研修のストーリー（便利さ → 失敗 → 解決 → 実感）を説明します。7枚目以降は、その日になってから使います。
*   研修のルール（Vibe Coding のルール）と、毎日の記録（比較シート、日報）を伝えます。
*   この研修は一人で進めること、あなたが講師役であること、作業はすべて受講者が行うことを伝えます。

### ミニ講義：LLM と Coding Agent（目安 15分）

*   スライドには該当するページがありません。手順書の「ミニ講義のポイント」を口頭で要約します。

### ハンズオン 1：アカウントと環境の準備

受講者が自分で登録します。あなたは手順を案内し、画面を確認するだけです。

| 手順 | 確認すること |
| :--- | :--- |
| 1. 作業用の Google アカウント | 自社のメールアドレスで作ったか。すでに作業用のアカウントがある人は、それを使ってよい |
| 2. Chrome の作業用プロファイル | プロファイルにそのアカウントでログインしたか。以降の作業は、すべてこのプロファイルで行う |
| 3. Claude in Chrome | 作業用プロファイルに追加し、社内契約の Claude アカウントでサインインしたか。ここで接続を確認する。以降は画面を直接見られる |
| 4. GitHub アカウント | 自社のメールアドレスで登録し、メール認証まで済んだか |
| 5. fork | 自分のアカウントに fork したか（fork の URL を `progress.md` に記録する） |
| 6. Codespace | recovery mode になっていないか。左下のブランチ、Claude のアイコン（✳）、`node -v` が v24 系か |
| 7. 信頼ダイアログとクリップボード | 「フォルダーを信頼して続行」を選んだか。クリップボードを許可し、貼り付けができるか |

*   Claude in Chrome がつながるまでは、受講者の報告やスクリーンショットで確認します。
*   Codespace は、自分のタブグループに開いて確認します（受講者が開いたタブは見えません）。

### ハンズオン 2：Claude Code へのサインイン

*   右側に最初から出ている「チャット」は Copilot です。Claude のアイコン（✳）から開いたパネルを使っているかを確認します。
*   認証コードは受講者が自分で貼り戻します。コードを共有しないよう、ここで一度注意します。
*   応答が英語なら、`/config` で language を `japanese` にするよう案内します。

### ハンズオン 3：ウォーミングアップ

*   モードを **Manual** にしてから始めさせます（最初は Auto になっていることがあります）。
*   話題ごとに新しい会話（＋）を始めさせます。
*   観察ポイントの答えを、受講者に言葉で説明してもらいます。失敗が起きなければ「失敗したとき」の観察は Vibe Chat に回します。
*   確認ダイアログで「常に許可」を押すと、`.claude/settings.local.json` が自動で作られます。今日は触らず、Day2 の権限設定の教材にします。

### ミニ講義：Vibe Coding とは（目安 15分）

*   ルール3つを確認し、「ここからは確認ダイアログの中身を考えずに承認する」と伝えます。

### ハンズオン 4：Vibe Chat を作る（目安 3時間）

*   開始時刻を記録します。指示の回数と、エラーを貼って直させた回数を、受講者に数えてもらいます。
*   モードは **Edit automatically** です。エディタで開いているファイルが会話に自動で添付されるので、外してから送るよう伝えます。
*   受講者が「コードを読んでもいいですか」と聞いたら、「今日は読まないでください」と答えます。
*   正しいやり方（テストを書かせる、計画をレビューする など）は、先に教えません。
*   起動したら、ポート転送の URL を受講者に開いてもらい、画面を一緒に確認します。

### チーム内の見せ合いの代わり（目安 20分）

完成した Vibe Chat を画面で見せてもらい、次の問いに答えてもらいます。答えは日報の材料になります。

*   何ができて、何ができなかったか
*   一番驚いたことは何か
*   このアプリを、そのままお客様に納品できると思うか

### 記録（目安 30分）

*   `git add vibe-chat && git commit` まで受講者が行ったことを確認します。
*   比較シートの Day1 欄と、日報を記入してもらいます。

## 遅れたときの調整

| 状況 | 調整 |
| :--- | :--- |
| 環境の準備に時間がかかった | ウォーミングアップの指示 2 を省略して、Vibe Chat に進む |
| Vibe Chat が目安を大きく超えた | 動いている範囲で打ち切る。動かない部分も Day2 の材料になる |
