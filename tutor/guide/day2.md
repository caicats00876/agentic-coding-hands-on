# Day2 チューター用ガイド

手順書：`../docs/Day2_VibeCodingの限界とAgenticCodingへの転換.md`

## この日のねらい

午前は Vibe Coding のまま機能を追加させ、壊れる、直らない、テストもない、という状況を体験させます。午後に「4つの作法」で解決の方向を示します。

## ステップごとの確認点

### 前日の振り返り（目安 15分）

*   日報の「AI が作ったアプリを、そのまま納品できるか」の答えを聞きます。

### ハンズオン 1：機能追加（60分で打ち切り）

*   Day1 と同じルール（コードを読まない、提案はそのまま承認）で進めます。
*   **60分で打ち切ります。**終わらないことも大切な記録です。
*   手戻りの回数、デグレの数、60分で終わったかを記録させます。

### ハンズオン 2：品質の検証

*   **AI に頼らせません。**受講者自身がターミナルでコマンドを実行します。Claude Code に「調べて」と頼もうとしたら止めます。
*   結果は比較シートに記入させます。

### ハンズオン 3：問題点の4分類（チーム活動の代わり、目安 30分）

1.  受講者が一人で、見つけた問題を書き出し、4分類の表を埋めます。
2.  あなたが問いかけて深めます。
    *   「その問題は、どの時点で防げたと思いますか」
    *   「同じことがお客様の環境で起きたら、何が困りますか」
    *   「一番痛かった問題はどれですか。理由も教えてください」
3.  一番痛かった問題を、午後のミニ講義の導入に使います。

### ミニ講義：4つの作法（目安 30分）

*   午前に受講者が挙げた問題を、4つの作法の表に当てはめて説明します。
*   要点は「AI に気をつけてとお願いするのではなく、仕組みで強制する」です。

### ハンズオン 4〜5：ガードレール

*   Day1 で自動的にできた `.claude/settings.local.json` があれば、それを例に「常に許可」が設定として残ることを説明します。共有する `settings.json` と、個人用の `settings.local.json` の違いも伝えます。
*   AI が `cat` などで `.env` を読もうと回り込むことがあります。起きたら「権限設定だけでは防ぎきれない」好例として扱い、日報に書かせます。
*   AI が拒否された操作を何度も試すときは、会話を止めて、受講者自身にターミナルで実行させます。
*   ブランチ保護は、受講者の fork の `main` に設定します。

### ハンズオン 6：Plan モードで不具合を直す

*   計画を**読んでから**承認させます。分からない点は AI に質問させます。

### ハンズオン 7：要件を読む（チーム共有の代わり、目安 30分）

*   受講者が、解釈が分かれそうな箇所に印を付けます。
*   あなたが「この言葉を AI はどう解釈すると思うか」と問いかけ、受講者なりの答えをメモにまとめさせます。Day3 で AI から質問されたときに使います。

### 記録

*   比較シートの「Vibe Chat」列がすべて埋まったか、日報を書いたかを確認します。

## 遅れたときの調整

| 状況 | 調整 |
| :--- | :--- |
| 機能追加が60分で終わらない | 打ち切る（予定どおり） |
| 午後が押した | ハンズオン 7 の一部を Day3 の朝に回す |
