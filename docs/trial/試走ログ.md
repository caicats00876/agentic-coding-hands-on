## Codespaces のマシンタイプ（2026-10-22）

*   **起きたこと**：4-core の Codespace では無料枠（月120コア時間 ＝ 4-core で約30時間）の消費が早く、Day1〜Day2 で 7.47 時間を使った。2-core にしようとしたが、`devcontainer.json` の `hostRequirements.cpus: 4` のため「Below dev container requirements」となり選べなかった。
*   **検討**：研修の処理（npm install、Vite と Hono の開発サーバー、Vitest、Playwright の E2E）は、2-core・8GB で動く範囲と判断した。Claude Code の推論はクラウド側で行われるため、Codespace の負荷は小さい。重いのは `npm install`、ビルド、E2E で、遅くはなるが止まることはないと見込む。**ただし、Day3 以降を 2-core で動かした実績はまだない。**
*   **教材の修正**：`hostRequirements` を `cpus: 2`、`memory: 8gb` に変更。Day1 1-7 で「New with options → Machine type 2-core」を選ぶ手順を追加。README と管理者向け準備の利用枠を 2-core（約60時間）基準に変更。トラブル対応に「重いときだけ 4-core に変える」「2-core が選べないときは fork の devcontainer.json が古い」を追加。
*   **次の確認**：Day3 のモノレポ構築と Day5 の E2E を 2-core で試し、かかった時間を記録する。
*   **使用量の実績（10月1日〜22日、Billing and licensing → Usage → `product:codespaces`、Group by: SKUs）**：Codespaces compute 4-core 11.3 時間（約45コア時間、定価 $4.07）、storage $0.04。請求額は $0（無料枠内）。残り約75コア時間で、2-core なら約37時間、4-core なら約19時間。Day3〜Day5 の見込み約22時間に対し、4-core では不足、2-core なら足りる。

### 2026-10-16 / Day1 ハンズオン 1（ブラウザ版 Codespaces での貼り付け）

*   **起きたこと**：ブラウザ版 Codespaces で貼り付けようとすると「ブラウザーのクリップボードから読み取ることができません。この Web サイトがクリップボードから読み取るためのアクセス権を付与していることを確認してください。」と表示され、貼り付けできなかった。
*   **原因**：ブラウザで Codespaces のサイト（`*.github.dev`）にクリップボードの読み取り権限が許可されていない。
*   **教材の修正案**：Day1 ハンズオン 1 に「初回の貼り付けでクリップボードの許可を求められたら許可する。拒否してしまった場合は、アドレスバー左の鍵アイコン → サイトの設定 → クリップボードを『許可』にして再読み込みする」を追加する。Day1 以降はプロンプトの貼り付けが前提なので、講師ガイドの「よくあるトラブル」にも載せる。
*   **補足**：試走では Codespace を Claude デスクトップアプリの内蔵ブラウザで開いていた。内蔵ブラウザにはサイト設定のメニューがないため、許可できなかった。Chrome で開き直して対応した。README の「ブラウザは最新の Google Chrome」の指定には理由がある（クリップボードやポート転送の許可を操作するため）ことを、一言書き添えるとよい。
*   **補足 2**：内蔵ブラウザの「ブラウザの設定」メニューには、Google Chrome で開く、URL をコピー、ビューポート、許可サイトを管理、Cookie などの項目しかなく、サイトごとのクリップボード権限の設定はない（「許可サイトを管理」は Claude のブラウザ操作の許可リストで、別物）。VS Code ドキュメント（GitHub Codespaces の Common questions）の「site permissions かアドレスバーのアイコンで許可する」手順は、内蔵ブラウザでは実施できない。

### 2026-10-16 / Day1 ハンズオン 1（ワークスペースの信頼ダイアログ）

*   **起きたこと**：Chrome で Codespace を開くと「このフォルダー内のファイルの作成者を信頼しますか?」というダイアログが出た。信頼しないと「制限モード」になり、ターミナルや拡張機能が制限される。
*   **原因**：VS Code の Workspace Trust 機能。Day1 の手順書に記載がない。
*   **教材の修正案**：Day1 ハンズオン 1 の手順 3 のあとに、「信頼ダイアログが出たら『フォルダーを信頼して続行』を選ぶ（自分の fork なので信頼してよい）」を追加する。あわせて、これもガードレールの一種であることを Day2 で触れるとよい。

### 2026-10-16 / Day1 ハンズオン 1（Claude Code on the web との混同）

*   **起きたこと**：受講者が「ブラウザで Claude Code を使う」つもりで claude.ai/code（Claude Code on the web）を開き、「GitHub へのアクセス権が必要」と表示されて使えなかった。
*   **原因**：「Claude Code」という名前のサービスが複数ある（VS Code 拡張、CLI、Web 版、デスクトップアプリ）。教材は VS Code 拡張を前提にしているが、Web 版との違いが書かれていない。
*   **教材の修正案**：README の研修環境、またはチートシートに「この研修で使うのは Codespace の中の VS Code 拡張。claude.ai/code（Web 版）やデスクトップアプリは使わない」と明記する。

### 2026-10-16 / Day1 ハンズオン 2（サインインの流れ）

*   **起きたこと**：メールアドレスでサインインしたところ、メールで認証コードは届かず、ブラウザに「許可（Authorize）」ボタンだけが表示された。許可すると `platform.claude.com/oauth/code/callback` のページに認証コードが表示され、それを VS Code 側に貼り付ける必要があった。手順書の「表示に従ってブラウザで認証します」だけでは、コードを貼り戻す工程がわからない。
*   **原因**：Codespaces はリモート環境なので、ローカルへの自動リダイレクトで認証を完了できず、認証コードを手動で貼り付ける方式になる。
*   **教材の修正案**：Day1 ハンズオン 2 に、①ブラウザで「許可」を押す、②表示された認証コードをコピーする、③VS Code の Claude Code パネルの入力欄に貼り付ける、という流れを明記する（スクリーンショット付き推奨）。あわせて「認証コードや callback の URL は他人に見せない・チャットに貼らない」という注意を加える。

### 2026-10-16 / Day1 ハンズオン 2（応答言語の設定）

*   **起きたこと**：サインイン後、受講者が Claude Code に「表示を日本語にしてください」と依頼した。Claude が `~/.claude/settings.json` に `"language": "japanese"` を作成し、「メニューやボタンは英語のまま」「devcontainer の再作成でホームディレクトリの設定が消えることがある」と説明した。
*   **原因**：教材に応答言語の設定手順がなく、受講者が自分で設定しようとした。
*   **教材の修正案**：チートシートか Day1 ハンズオン 2 に「応答を日本語にする設定」を載せる。リビルドで消えないよう、devcontainer の postCreateCommand で設定するか、リポジトリの `.claude/settings.json` に含めることを検討する（ただし Day2 で `.claude/settings.json` を自分で作る流れと衝突しないか確認が必要）。

### 2026-10-16 / Day1 ハンズオン 3（モードの名称と既定値）

*   **起きたこと**：Claude Code 拡張のモードメニューは **Manual / Edit automatically / Plan / Auto** の4つで、ほかに Effort（Medium）と Ultracode の切り替えがあった。最初は「Auto」が選ばれており、ウォーミングアップの「許可を求めるダイアログが出ることを確認」が成立しない可能性があった。
*   **原因**：チートシートのモード表は「編集前に確認 / 自動で編集 / Plan モード」の3つで、実際の表示名（Manual）と一致せず、Auto モードの記載もない。Day1 ハンズオン 3 にもモードの指定がない。
*   **教材の修正案**：チートシートのモード表を実際の表示名（Manual、Edit automatically、Plan、Auto）に合わせ、Auto の説明（安全チェックを通った操作を自動承認し、危険なものだけ止める）を加える。Day1 ハンズオン 3 の冒頭に「モードを Manual にする」を追加する。Effort と Ultracode は研修では既定のままでよいことも書いておく。

### 2026-10-19 / Day1 再開時（.claude/settings.local.json の自動生成）

*   **起きたこと**：受講者が Claude Code に「現在のアカウント情報」を尋ねた際、コマンド実行の許可で「常に許可」を選んだ結果、リポジトリ直下に `.claude/settings.local.json`（`allow: ["Bash(claude auth *)", "Bash(git config *)"]`）が自動で作られた。
*   **原因**：Claude Code は「常に許可」した操作を `.claude/settings.local.json` に保存する。リポジトリの `.gitignore` にこのファイルが含まれていないため、`git add .` をするとコミットされてしまう。
*   **教材の修正案**：`.gitignore` に `.claude/settings.local.json` を追加する。Day2 の権限設定（`.claude/settings.json`）の説明で、「共有する settings.json」と「個人用の settings.local.json（Day1 で『常に許可』を押すと勝手にできる）」の違いを扱う。Day1 で自然に生まれるこのファイルは、Day2 のガードレールの導入教材としても使える。

### 2026-10-19 / Day1 ハンズオン 3（ウォーミングアップの結果）

*   **起きたこと**：Chrome でクリップボードを許可したあと、貼り付けができた（Day1 に追記した手順で解決したことを確認）。指示 1（README の要約）は Read 1 回、1 分以内。指示 2（`hello/` スクリプト）は Manual モードで、ファイル作成時と `node` 実行時の両方で確認ダイアログが出て、Allow で許可した。約 1 分で完了。AI は頼まれていないタイムゾーン指定（Asia/Tokyo）を加え、「コミットしていない」と報告した。観察ポイント「失敗したとき自分で直そうとしたか」は、失敗が起きず観察できなかった。
*   **原因**：指示が簡単すぎて失敗が起きにくい。
*   **教材の修正案**：観察ポイント 3 は「起きなければ Vibe Chat で観察する」と注記する。また、作った `hello/` をどうするか（コミットしない、削除してよい）を書いておく。確認ダイアログのボタンは英語（Allow など）なので、チートシートにボタン名と意味（Allow／常に許可／Deny）を載せるとよい。

### 2026-10-16 / Day1 ハンズオン 2（チャットパネルの取り違えリスク）

*   **起きたこと**：Codespace の右側のパネルに VS Code 標準のチャット（「エージェントを使用して構築する」「エージェントの指示の生成」）が表示されていた。Claude Code のチャットパネルと見た目が似ていて、受講者が取り違えるおそれがある。
*   **原因**：VS Code 標準のチャット（GitHub Copilot）が既定で右側のセカンダリサイドバーに表示される。
*   **教材の修正案**：Day1 ハンズオン 2 に「右側に最初から出ているチャットは Claude Code ではない。Claude のアイコン（オレンジ色）から開いたパネルを使う」と、見分け方を追記する。可能ならスクリーンショットを付ける。devcontainer の settings で標準チャットを非表示にすることも検討する。
