# 道具の使い方（はじめに読む）

この研修では、いくつかの道具を使います。仕組みを詳しく知らなくても大丈夫です。**何をする道具か、どこを触ればよいか**だけ分かれば進められます。
分からない言葉が出てきたら、その場で AI チューターに「〇〇って何？」と聞いてください。

## 2つの Claude

この研修でいちばん大事な図です。Claude は2か所に登場し、**役割も会話も別々**です。

![2つの Claude](images/two-claudes.svg)

| | ① AI チューター | ② Claude Code |
| :--- | :--- | :--- |
| どこにいる | Claude デスクトップアプリのチャットで開いた、研修プロジェクト「AgenticCoding研修」 | Codespace（VS Code）の右側のパネル（✳） |
| 役割 | 研修の先生。手順を案内し、画面を確認する | 開発の相手。アプリのファイルを書き、コマンドを実行する |
| 話しかけること | 「できた」「分からない」「次は？」 | 教材のプロンプト、「直して」「起動して」 |
| お互いの関係 | ② との会話の中身は知らない。画面を見て確認する | ① のことは知らない |

AI チューターは、指示を出すときに「**どこで何をするか**」を必ず書きます。

| 書き方 | すること |
| :--- | :--- |
| 【Claude Code に送る】 | Codespace の ✳ パネルに `Ctrl+V` で貼り付けて送信する |
| 【ターミナルで実行】 | Codespace のターミナルに `Ctrl+V` で貼り付けて Enter |

> [!IMPORTANT]
> Codespace の VS Code では、**貼り付けは必ず `Ctrl+V`** を使います。右クリックメニューの「貼り付け」は使えないことがあります。
| 【ブラウザで操作】 | Chrome の画面で、ボタンを押したり入力したりする |
| 【チューターへ】 | Claude デスクトップアプリ（AI チューター）のチャットで教える |

### ChatGPT との違い

ChatGPT などのチャットアプリは、**会話で答えを返す**道具です。Claude Code は、それに加えて**手を動かせる**道具です。ファイルを作る、書き換える、コマンドを実行する、といったことを自分で行います。
そのため、Claude Code は作業の前に「このファイルを書き換えてよいか」「このコマンドを実行してよいか」と確認してきます。

## Codespace（VS Code）の画面

![Codespace の画面の見方](images/vscode-layout.svg)

使う場所は5つだけです。ほかのボタンは触らなくてかまいません。

| 番号 | 名前 | すること |
| :--- | :--- | :--- |
| 1 | エクスプローラー | ファイルの一覧。クリックするとファイルが開く |
| 2 | エディタ | ファイルの中身を見る。Day1 は中身を読まなくてよい |
| 3 | ターミナル | コマンドを貼り付けて Enter を押す場所 |
| 4 | Claude Code | 開発の指示を出す場所。左端か右上の ✳ で開く |
| 5 | ステータスバー | 左下に、今のブランチ（作業の枝）の名前が出る |

## ターミナル（コンソール）

文字で PC に命令する場所です。

1.  教材やチューターの指示にあるコマンドをコピーします。
2.  ターミナルをクリックして、`Ctrl+V` で貼り付けます（右クリックの「貼り付け」は使いません）。
3.  `Enter` を押します。

*   行の先頭の `$` は「入力を待っています」という印です。`$` はコピーしません。
*   結果の文字が流れても、意味を全部理解する必要はありません。最後の数行を AI チューターに見せれば、うまくいったか判断してくれます。
*   止まらなくなったら `Ctrl+C` で止まります。

## GitHub と Git

| 言葉 | 一言でいうと |
| :--- | :--- |
| GitHub | プログラムを保存しておくクラウドの置き場所 |
| リポジトリ | 1つのプロジェクトのフォルダ。この研修の教材も1つのリポジトリ |
| README.md | リポジトリの説明書。**リポジトリを開いたら、まずこれを読む** |
| fork（フォーク） | 他の人のリポジトリを、自分のアカウントにまるごとコピーすること |
| Codespaces | GitHub が用意する、ブラウザで使える開発用のパソコン |
| Git | ファイルの変更の履歴を残す道具 |
| コミット（commit） | ゲームのセーブのように、今の状態を記録すること。失敗しても戻れる |
| プッシュ（push） | 記録した内容を GitHub に送ること |
| ブランチ | 作業を分けるための枝。左下に今の名前が出る |
| Pull Request | 作業の枝の変更を、本線に取り込むための申請（Day3 から使う） |

Git のコマンドは、教材に書かれたものをそのまま使えば大丈夫です。

## Chrome の作業用プロファイル

普段使っている Chrome とは別に、研修専用の Chrome を用意します（Day1 で作ります）。研修用のブックマークや拡張機能を、ここにまとめておきます。研修の作業は、すべてこの作業用プロファイルで行います。
