# PART 1 LLMユーザーとしての基礎知識

Coding Agentは、大規模言語モデル（LLM）の能力を最大限に活用し、私たちのコーディング作業を強力に支援します。Coding AgentとはAIエージェントの一部です。AIエージェントには自然言語で依頼・指示を出していきますが、技術の核となるLLMへの知見を深めることで、より強力に扱うことができます。込み入った話はそれ自体が1冊の書籍になり得るくらいの深さのあるトピックですが、本書ではあくまでCoding Agentを使い始めるにあたって、知識の裏付けとして最低限の理解が必要な箇所に絞って理解しましょう。

## 1.1 大規模言語モデル（LLM）とは
「大規模言語モデル（Large Language Model, LLM）」とは、インターネット上の膨大なテキスト（書籍、記事、ウェブサイト、コードなど）を用いて事前学習された、非常に巨大なニューラルネットワークモデルです。その中でもChatGPTやGeminiなど、私たちが普段使っているAIチャットの核となるモデルは有名です。

LLMの基本的な仕組みは、ある単語や文の次に来る単語の予測です。LLMは与えられたテキストを「トークン」と呼ばれる単位に分割し、次に続くトークンを予測することで、人間のような自然な文章を生成します。
図のように、LLMは文章を一度にまとめて生成するのではなく、「これまでの文脈を踏まえて、次に来そうな言葉（トークン）を選ぶ」という処理を繰り返しています。つまりLLMは、確率的な予測を高速に積み重ねることで文章を生成しているのです。

## 1.2 モデルとプロバイダ
LLMは、様々な企業や研究機関によって開発され、たくさんの種類があります。ここではまず「モデル」と「プロバイダ」、この2つの基本的な言葉を整理しておきましょう。

### 1.2.1 モデル
モデルは、まさにLLMそのものであり、「GPT-5.4」「Claude Sonnet 4.6」「Gemini 3.1 Pro」といったAIの頭脳の部分です。モデルには様々な種類があり、それぞれ得意とするタスクや性能、サイズが異なります。
近年は画像や音声、動画などの様々なデータ形式に対応する「マルチモーダル」モデルが一般化しつつあります。
また、上位のモデルには **Reasoning（推論）** 機能を持つものがあります。Reasoningとは、複雑な問題を段階的に考えて解決する能力です。このような段階的思考は **CoT（Chain of Thought、思考の連鎖）** と呼ばれます。

### 1.2.2 プロバイダ
プロバイダ（Provider）とは、モデルをサービスとして提供する企業や組織を指します。プロバイダは、自社あるいは他社のモデルをAPIとして公開し、開発者はこのAPIを呼び出すことで、自らのアプリケーションにLLMの機能を組み込むことができます。

### 1.2.3 プロバイダの種別
プロバイダは大きく分けて次の3つの形式があります。
*   **モデル開発元**: 最新機能やβ版機能などの先端機能へのアクセスが提供されているのが特徴です。（例: OpenAI、Anthropic）
*   **ホスティングプラットフォーム**: モデル開発はせず、専任のプロバイダとしてサービス提供している事業者です。（例: OpenRouter）
*   **マネージドサービス**: パブリッククラウドの1サービスとしてプロバイダが提供されている場合もあります。高度なセキュリティ機能やガバナンスの高さが優位点です。（例: Amazon Bedrock、Azure OpenAI Service、Vertex AI）

### 1.2.4 どのモデルが使われているか
2026年1月現在、Coding Agentでよく使われているモデルは次の通りです。
*   **Claudeシリーズ（Anthropic）**: Claude 3.5 Sonnet V2、Claude Sonnet 4.5など、高度なコーディング性能を備える。
*   **GPTシリーズ（OpenAI）**: 汎用モデルのGPT-5.2、コーディングに最適化されたGPT-5.2-Codexなど。
*   **Geminiシリーズ（Google）**: 長いコンテキストウィンドウ（100万）とコーディング性能を併せ持つGemini 3 Proなど。

### 1.2.5 モデル選定の留意点
Coding Agentで利用するLLMモデルを選択する際には、一般的な推論性能だけでなく、**「コーディング性能」「レスポンス速度」「推論コスト」**を総合的に考慮する必要があります。
*   **コーディング性能**: SWE-benchなどのベンチマークスコアだけでなく、実際のコードベースでのトライアル検証が重要。
*   **レスポンス速度**: 応答の速さが生産性に直結するため、手戻りを防ぐために高性能モデルを扱うほうがトータル時間を短縮できる場合がある。
*   **推論コスト**: サブスクリプション型ツールでも裏側はAPI課金であるため、サービス単体ではなくAPIレイヤーも含めたモデル選定が必要。

### 1.2.6 プロバイダ選定時の留意点
マネージドサービスでは「送信データは学習に利用しない」のが一般的ですが、ホスティングプラットフォームでは設定によって異なります。機密性の高いコードを扱う際は、学習フラグの有無やログ保持期間など、データポリシーを確認しましょう。

### 1.2.7 リージョン/ホスティング国の考慮
世界的なGPU不足を背景に、推論トラフィックが空きリソースのある国・リージョンにルーティングされる（クロスリージョン推論）仕組みが一般化しつつあります。実務では「どの範囲まで越境を許容するか」を明らかにし、ルールを整合させることが重要です。

## 1.3 プロンプト
LLMにおけるプロンプトとは、モデルに対し、タスクや質問を伝えるための指示文を指します。

### 1.3.1 プロンプト種別
*   **システムプロンプト**: エージェントの基本的な振る舞いを定義します。「あなたは熟練したエンジニアです」のような役割や、守るべきルールを設定します。
*   **ユーザープロンプト**: エージェントへの指示であり、「このコードをリファクタリングして」といった具体的な問題やタスクの指示を指します。

### 1.3.2 プロンプトエンジニアリング
LLMから望ましい出力を得るためにプロンプトを設計・最適化する技術です。代表的な原則として以下があります。
*   曖昧な表現を避けて、具体的な指示を与える（明確さ）
*   タスクの背景情報を与え、期待する出力形式を明示する（文脈の明示）
*   複雑なタスクを段階的に分解し、順序や構成を整理する（構造化）
*   期待する出力の具体例を提供する（例示）

### 1.3.3 トークンとコンテキストウィンドウ
*   **トークン**: LLMがテキストを処理する際の最小単位です。
*   **コンテキストウィンドウ**: LLMが一度に処理できるテキストの長さ（トークン数）の上限です。

### 1.3.4 プロンプトキャッシュ
一度送信したプロンプトの一部を「キャッシュ」として保存し、再利用することでレスポンス時間の短縮とコスト削減を実現する技術です。長いソースコードを繰り返し読み込むCoding Agentにおいては、プロンプトキャッシュが非常に有効です。

### 1.3.5 ハルシネーション
LLMが事実と異なる情報を、あたかも本当のように答えてしまう（幻覚）現象です。情報（コンテキスト）不足によって引き起こされることが多いため、外部の正確な情報源を与えて根拠に基づかせる **グラウンディング**（RAGやTool Useなど）の仕組みが重要になります。
