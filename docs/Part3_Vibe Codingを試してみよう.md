# PART 3 Vibe Codingを試してみよう

ソフトウェア開発はこれまで、人間の手によって精緻に組み上げられてきました。しかし今、その前提が大きく変わろうとしています。AIエージェントが主体となる「Agentic Coding」という新しい開発スタイルの登場により、人間はすべてを作る存在から、最終的な品質を担保する意思決定者へと役割をシフトしつつあります。PART3では、その第一歩として、「何をAIに委ねるのか」という感覚をつかむためにVibe Codingを実践していきます。

## 3.1 Coding Agentとの開発スタイル
従来のソフトウェア開発では、要件定義から実装までの開発工程の大部分を人間が担ってきました。AIエージェントが主体となる開発方式である **Agentic Coding** では、これらの工程の多くを自律的なLLMエージェントに委ね、人間は最終責任者として品質確認と意思決定を担います。人間が意図を示し、AIが自律的に作り、人間が責任をもって仕上げるという、AI主体＋人間協働の体制を築きます。

## 3.2 Vibe Codingとは
Vibe Coding（バイブコーディング）とは、プログラマーがコードの厳密な仕様や詳細なロジックを意識せずに、「実現したいことの雰囲気やノリ（Vibe）」をAIに伝え、コード生成や修正の大部分をAIに「委ねる」新しいプログラミングスタイルを指します。
どのように作るか（How）は気にせず、プロダクトの目的やユーザーへの提供価値（What）を重視し、LLMの創造性に委ねるのが特徴です。

### 3.2.1 本書でのVibe Codingの定義
本書では、Vibe Codingを次のように定義して実践します。
*   コードの実装は意識せずに自然言語の指示でコーディングエージェントへ依頼します。
*   コーディングエージェントが実装した内容は、そのまま承認します。
*   コードベースは確認せず、外形的に気になる点を修正させて完成へ導きます。

## 3.3 本書における開発環境の前提
ここからのハンズオンは、次の前提で行います。
*   **Gitリポジトリ**: GitHub
*   **WebIDE（VS Code & 開発環境）**: GitHub Codespaces
*   **コーディングエージェント**: Cline
*   **利用するプロバイダ**: Amazon Bedrock (AWS) -> Google AI Studio で代用
*   **利用するモデル**: Claude Sonnet 4 (Anthropic) -> Gemini3 Flash で代用

### 3.3.1 Clineを選定した理由
ClineはOSS（Apache License 2.0）であり、無償のVS Code拡張として導入できるため、個人用途でも商用用途でも導入ハードルが低い点がメリットです。また、利用できるLLM APIの選択肢が広く、Amazon BedrockやVertex AIなどエンタープライズ向けの環境から、安価なAPIまで幅広く利用可能です。

## 3.4 Clineのセットアップ
ハンズオンを実施するための環境構築を行います。
1.  **アカウントの作成**:ハンズオンで使用するサービスのアカウントを作成します
 - Google: GoogleアカウントはGoogle AI Studio（Gemini）を利用するために必要です。 [Googleアカウント作成](https://accounts.google.com/signup)
 - GitHub: GitHubアカウントはリポジトリ管理とCodespaces利用のために必要です。 [GitHubアカウント作成](https://github.com/join)
2.  **GitHubリポジトリの作成**: このリポジトリを各自のGitHubアカウントでフォークして使用します。
3.  **GitHub Codespacesの作成**: ブラウザからアクセスできるクラウドベースの開発環境「GitHub Codespaces」を利用します。これにより、AIエージェントに操作を委ねてもローカルマシンに影響しない安全なサンドボックス（隔離）環境を構築できます。`devcontainer.json` を設定し、必要なツールを自動でインストールさせます。
4.  **AWS認証情報の設定**: AWS Bedrockを利用するために、AWS SSO（IAM Identity Center）を用いて認証情報を設定します。
5.  **Clineのセッティング**: VS Code拡張機能のClineをインストールし、API Provider（Amazon Bedrock）やModel（Claude Sonnet 4）を指定して初期設定を完了させます。

## 3.5 Vibe Codingの実践
「イケてるチャットツール『Vibe Chat』を作ってください」というような「ノリ（Vibe）」を重視した大まかなプロンプトを用いて、実際にアプリケーションを構築させます。

### 3.5.1 プロンプト投入
基本コンセプト、コア機能、拡張ステータス、技術スタックなどの要件をClineに投げかけます。エージェントの自律的な作業を妨げないよう、「Auto-approve（自動承認）」の設定を有効にします。

### 3.5.2 エージェントとの対話的な設計
Clineが提案する技術スタックの確認や、フェーズ分けされた詳細な実装計画（Plan）が提示されます。人間はこれらを確認し、承認して実行させます。

### 3.5.3 ドキュメントと環境設定の作成
Clineが「Actモード」に切り替わり、プロジェクト計画書やアーキテクチャドキュメント、`package.json` などの設定ファイルを自動生成し始めます。

### 3.5.4 コア機能の実装
バリデーションライブラリ（Zod）を使用したスキーマの作成や、フロントエンド・バックエンドの依存パッケージのインストールをClineが自律的に行います。

### 3.5.5 フロントエンドの構築とプロジェクト完成
ReactやTailwind CSSを用いてUIコンポーネントが作成され、開発サーバーが起動します。コンパイルエラーなどが発生した場合も、エラー内容をそのままClineに投げて自己修復（デバッグ）させます。最終的に、ブラウザ上で動作するチャットアプリケーション（Vibe Chat）が完成します。

## PART 3 Summary
PART3では、Vibe Codingの概念を理解し、Coding Agentの「Cline」を使って実践しました。
まず、Coding Agentとの開発スタイルとして、従来の人間主体の開発からAIエージェント主体の開発への転換を理解し、次にエージェントが安全に動作できる隔離された開発環境を構築しました。
Vibe Codingの実践では、技術スタック選定、アーキテクチャ設計、実装、デバッグまでのプロセスの大部分をエージェントに委ね、約2時間半の実装時間と$10弱のコストで、基本的な機能を備えたプロトタイプが完成しました。驚くべき速度であり、Coding AgentとVibe Codingの威力が分かります。
一方で、Vibe Codingをプロダクション開発にそのまま適用するには課題が残ります。次のPART4では、この体験を踏まえた上で、実用に向けた課題と解決策を詳しく見ていきます。
