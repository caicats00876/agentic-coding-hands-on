# PART 5 Agentic Coding - 開発基盤構築

本PART以降のハンズオンでは、PART3のVibe Codingとは異なり、実務に耐えるプロダクション志向のスタイルであるAgentic Codingを紹介します。具体的にはPART4で示した「4つの作法（要件具体化 / 自動テスト / 規約維持 / ガードレール）」を、エージェントとの開発プロセスに落とし込み、責任ある商用システム開発でどのように活かしていくかを紹介します。ここではその前段となる開発環境設計からガードレール作成までの実現方法を紹介します。

## 5.1 Agentic Codingとは

### 5.1.1 「4つの作法」を振り返る
前Partでは、エージェントを安全に活用するための「4つの作法」を紹介しました。ここでは、4つ目のガードレール内の項目を含めた7項目を再掲します。
1. 要件定義（プロンプト）の具体化
2. 自動テストの積極的な採用
3. 規約・スタイルの維持
4. セーフティネットとしてのガードレール
   - バージョン管理システムの導入
   - 開発環境の隔離
   - 権限管理
   - 継続的インテグレーションの整備

### 5.1.2 Agentic Codingの準備に必要なもの
改めて残りの5項目を紹介します。

*   **要件定義（プロンプト）の具体化**
    要件定義、つまりユーザーが渡すプロンプトの具体化については、「計画策定」の機能を利用します。Clineでは `Plan` モードと `/deep-planning` コマンドを活用していきます。Planモードではファイルの変更は行わず、コードベースを読み込んで文脈を把握しつつ、要件理解と戦略に専念します。
*   **自動テストの積極的な採用**
    生成物を検証するプロセスはもはや必須です。自動テストを扱う方針をルールファイルに明記して、環境構築にも必要なライブラリ等を導入しましょう。本ハンズオンではテスト駆動開発（TDD）を遵守するように記載します。
*   **モノレポとライブラリ選定**
    これから進めるハンズオンは、GitHubおよびGitHub Actionsを前提とするTypeScriptのモノレポを題材とします。自動テストのライブラリには `Vitest` やE2Eテスト用の `Playwright` を、実行時のバリデーションを行うために `Zod` を選定します。
*   **規約・スタイルの維持**
    コーディングでは、自動テストだけでなく、規約やスタイルの維持も引き続き重要です。フォーマッターやリンターによる処理を委ねるため、今回はRust製の高速なツール `Biome` を採用します。
*   **権限管理**
    Agentic Codingでは、エージェントが自由にコードを編集できるため、特にAWSのようなクラウドリソースへの権限については、管理者権限のような強い権限を避け、誤操作による意図しないリソースの作成や削除を防ぐ必要があります。そのため、実行するタスクに必要な最小限のIAMポリシーを定義するのが理想です。
*   **継続的インテグレーションの整備**
    AIエージェントが生成したコードを自動的に検証し、品質を早期にフィードバックするためには、継続的インテグレーション（CI）の整備が不可欠です。本ハンズオンでは `GitHub Actions` を利用します。

## 5.2 開発環境の準備

ここからは、PART3で用意した手順を起点にしながら、Agentic Codingの準備を進めていきます。

### 5.2.1 GitHub Repository / GitHub Codespaces
まずはGitHub Codespacesを立ち上げます。「Repository name」にはPART3で作ったリポジトリとは異なる任意の名前（例：`my-agentic-coding-example`）を入力して、新規リポジトリとCodespaces環境を作成し、作業ブランチ（`agentic-coding-setting` など）を切ります。Codespaces上で扱う基本的なツールを導入するために、Dev Containerを設定します。

### 5.2.2 AWS Credential / Cline
次に、AWS IAM Identity Center（旧AWS SSO）経由でIAM権限をCodespaces環境で扱えるようにし、インストールしたClineがAmazon Bedrock経由でLLMモデルへアクセスできるように設定します。

### 5.2.3 Ruleファイルの作成
Cline Rules機能を使って、プロジェクト固有のルールを設定します。`.clinerules/common.md` というMarkdownファイルを作成し、以下の内容を書き込みます。
*   **Policy**: セキュリティを最優先とし、KISS原則に従う。
*   **Doc**: `implementation_plan.md` を用いて実装を管理する。
*   **Tips**: CLIはPagerを使わないなど。
*   **Test**: Kent Beck準拠のTDDを順守する。
*   **Taskの完了条件**: 常にデグレードがないことを確認する、カバレッジは80%以上を必達とするなど。

### 5.2.4 Workflowsファイルの作成
ルールファイルと併せて、Workflowsも設定します。ClineのWorkflows機能は定型動作をAIワークフローとして定義し、ショートカットのように扱えます。
`save-implementation-plan`（計画書の保存）や、`selfcheck`（要件や設計が完了しているかの自己レビュー）といったワークフローを定義したMarkdownファイルを作成します。

### 5.2.5 Ignoreファイルの作成
プロジェクトで不要なファイルやディレクトリをClineのコンテキストから除外するには、`.clineignore` ファイルを作成します。APIキーやシークレットの漏洩を防ぐため、`.env` ファイルや `~/.aws/` ディレクトリなどを指定して除外します。

### 5.2.6 モノレポ環境の構築計画策定
ルール設定が完了したら、次に `/deep-planning` コマンドを使ってモノレポ環境の構築計画を立てましょう。フロントエンド（React, Vite, Tailwind CSS）、バックエンド（Hono）、インフラ（AWS CDK）といった技術スタックを指定し、プランを作成します。

### 5.2.7 モノレポ環境の構築
計画策定が完了したら、「Start New Task With Context」をクリックして実装を開始します。まずはルートの `package.json` の設定から始めます。
Clineはタスクリスト（Focus Chain）を提示し、ルート環境の構築、共通パッケージの定義、Backend / Frontend の基本的な設定を順調に作成し完了させます。最後に `implementation_plan.md` を作成して計画書として保存します。

構築した環境をClineにセルフチェック（`/selfcheck`）させます。テストが通らない部分があれば、自動的に修正と再テストを行い、品質を高めます。

## 5.3 モノレポ環境の強化

### 5.3.1 Agentic Codingに必要な作法の振り返り
一通り環境設定を進めました。ここからは、まだ未対応だった「権限管理」や「継続的インテグレーションの整備」などを進め、モノレポ環境をよりプロダクション仕様に高めましょう。
以下のプロンプトをClineに入力します。
`/deep-planning npm workspacesのセキュリティを強化したい。`

### 5.3.2 モノレポ環境の強化施策
プロンプトを仕様駆動開発（deep-planningモード）で実行すると、Clineが現状分析を行い、未設定のツール群でセキュリティを強化するロードマップを示してくれます。
*   Renovate（依存関係の自動更新）
*   Husky + lint-staged（コミット前チェック）
*   Gitleaks（シークレットスキャン）
*   npm audit の自動化
*   GitHub Actionsのセキュリティ強化設定

### 5.3.3 モノレポ環境強化の検証
計画策定が完了したら、「Start New Task With Context」をクリックして、セキュリティ強化プランを実装していきます。
一通りの作成・更新が完了した後は動作確認を実施しています。脆弱性を確認するnpmスクリプト（`npm run audit-check`）についても、問題なく実行できることを確認します。さらに、CI/CDで Lint / Format / Test / Typecheck が正しく実行されるように整備します。

## 5.4 動作確認

環境構築が完了したら、実際にアプリケーションを起動して動作確認を行います。
起動時のつまずきどころとしては、ポート競合や環境変数の不足が多いように感じます。問題が起きたら、まずはプロセス一覧とdotenvやAWSプロファイルなどの設定値を疑って、Clineと一緒に解決しましょう。

*   **Frontendの起動**: `npm run dev` でReactアプリケーションが正常に起動し、ブラウザで「Hello World」と表示されることを確認します。
*   **Backendの起動**: `npm run dev` でバックエンドサーバーを起動し、`curl` コマンドでAPIエンドポイントにアクセスして、期待通りに応答（JSONデータなど）が返ってくるかを確認します。

これで基盤となる環境の構築がすべて完了しました。いよいよPART6では実装に移ります。

## PART 5 Summary

本PARTでは、Agentic Codingのための開発基盤構築を行いました。PART4で示した「4つの作法」（7つの項目）を実装に落とし込み、エージェントとの協働開発に耐えうる環境を段階的に整備しました。

まず、エージェントの振る舞いに一貫性を持たせるために、Cline Rulesを用いてプロジェクト固有のルールとワークフローを定義しました。その上で仕様駆動開発（`/deep-planning`）を活用して要件を具体化し、段階的な実装計画を策定しました。

セキュリティ面では、コミット前チェックを導入し、認証情報の混入やフォーマット崩れを自動で防止する仕組みを整えました。さらにCI/CDをGitHub Actionsで整備し、各種チェックを自動で実行しています。また、エージェントの出力を鵜呑みにしないように、セルフチェック（`/selfcheck`）ワークフローを通じた検証プロセスを確立しました。

これらの開発基盤により、エージェントと安全かつ効率的に開発を進められる環境が整いました。次のPART6では、この環境を活かした実践的な開発手法について解説します。
