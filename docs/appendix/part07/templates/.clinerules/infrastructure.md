## 開発スタイル

- 既存コードベースの尊重
    - 重複実装の禁止。実装前に既存コードをチェックし、重複がないかを確認
- ライブラリ導入
    - 標準ライブラリや既存ライブラリで実装できるものは、原則導入しない
    - 新規にライブラリを導入する場合、ライセンスはMIT、Apache2.0、BSDのみとする。
- コード変更は関係がある箇所のみ。
    - リファクタリングが必要な箇所については、実装は行わず指摘のみに留める。
- Git Commitは明示的な依頼がある場合のみ
- Debugは1観点ごとに実施する。他の観点を試す前に必ず正確に元の状態に戻す。

## AWS

- AWSの知識はAWS Knowledge MCP Serverから取得する。
    - 最新のベストプラクティスや推奨設定を参照すること
    - サービスの制限事項や料金体系も考慮すること
- 環境はAWS CDK V2(TypeScript)で管理する。
    - AWS CDKの知識はAWS CDK MCP Serverから取得する。
    - 各種リソース作成はL2/L3 Constructを優先する。
    - 過度なモジュール化は避け、シンプルな構成を保つ
    - .grant, .connect, addDependsOnなどのメソッドを活用し、適切な抽象化を行う
    - スタックは原則分離しない。以下の要件の場合のみ。
      - デプロイ時にCloudFormationのハードリミット起因で失敗する場合
      - デプロイ時にCloudFormation外のアクションが必要な場合
      - マルチアカウント・マルチリージョン対応が必須な場合
    - 品質管理
        - Vitest、Biome、aws-nagを使い、各イテレーション毎にTDDスタイルで進める。
        - snapshotテストをイテレーション毎に実施し、意図しない変更がないかを確認する

## Deploy

- 本番環境へのデプロイは段階的に行い、各段階で動作確認を実施する
- cdk driftコマンドを使って、一切のAWS環境との差分を検出し、コードとの整合性を保つ
- デプロイ前には必ずcdk diffで変更内容を確認する
